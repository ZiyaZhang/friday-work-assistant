# Friday for DSH

在 DSH 中继续自己的 Friday 飞书私聊，查看和修改同一份个人清单、打开工作结果、补充要求或停止执行。

## 安装与配对

在 DSH 插件管理中添加此目录。中转地址默认是占位符：先部署 `cloudflare/friday-oauth`，再把 `lib/transport.js` 里的 `RELAY` 改成自己的地址。

1. 在 Friday 飞书私聊发送 `连接 DSH`。
2. 打开配对链接，将完整地址粘贴到 DSH 的 Friday 面板，为设备命名。
3. 在飞书核对设备名称及验证码，确认连接。链接十分钟有效，设备连接三十天有效。

账号连接页可以撤销任一设备；DSH 中也可以断开本机。设备配对只连接当前本人的 Friday。GitHub、Gmail 等提供方凭据不交给插件或模型。

## 当前能力

- 与飞书私聊使用同一服务端主会话。
- 个人清单、来源链接、GitHub 事项和等待事项。
- 同一工作内补充要求，查看最终结果，停止执行、取消工作。
- 在两端查看与修改同一邮件草稿；发送前确认收件人与正文，发送不明时先核对回执。
- 选择已交付的工作背景，在本机目录启动独立 DSH 会话；沿用本机默认模型、工具权限和账号。结果回到同一条 Friday 本机工作记录，两端均可停止。
- 本地保存操作编号和加密请求，重试不会重复修改清单或创建工作。
- 在「连接」里连接本人的 GitHub（App 授权或个人令牌）、Gmail，显示实际账号和撤销入口。
- 添加个人 MCP：公网 HTTPS 的 Streamable HTTP 地址，可选 Bearer 令牌；检查工具目录后加密保存凭据。读取和调用都只开放给本人的交互任务，群聊无法使用个人连接。

本机执行首次上限为 10 分钟、20 步。断线会停止当前执行，重启只核对已有回执，不自动再次提交模型请求。未同步的结果保留原编号；用户可在 DSH 原会话继续。Gmail 真实连接仍需完成提供方 OAuth 配置和邮箱验收。

MCP 首次连接不会自动授权所有工具。用户可选择服务声明为只读的工具用于任务，其余调用在飞书私聊展示服务、操作和参数后确认。工具元数据变化后需要重新连接；断开会立即使旧工具和结果来源失效。调用超时后保留“回执未确认”，不自动重做。当前不支持第三方 MCP 的 OAuth、stdio、本地或内网服务；远端工具请求有时限，工具服务自身的长时异步作业尚未接入。

## 开发

从 Friday 仓库根目录运行 `node scripts/build-dsh-plugin.mjs` 更新共享的加密协议文件。Host 通过 DSH Connection 的 Fetch 注册入口提供 `/api/friday/*`，复用已有登录边界；前端不直接访问配对密钥。开发中修改 Host 模块后需要完全退出并重新启动 DSH；仅切换插件开关仍会复用 Node 的模块缓存。

内容在 Friday 服务端和已配对设备之间加密传输。Cloudflare 中转只暂存密文。设备凭据保存在当前 DSH profile 对应的本地目录，目录权限 0700、文件权限 0600。
