# 版本与发布核查

**合入 ≠ 发布。** 这是这条路径存在的全部理由：PR 合并了、Issue 关了，都不代表用它的人能拿到。有人问"修好了吗"，他问的是"我升级之后是不是就没这个问题了"。

用 `github_releases`：

- **最新版是什么**：直接看 `latest`；它是预览版时，`latest_stable` 才是正式版。**别把 alpha 说成正式发布**。
- **这个修复进哪个版本了**：`contains` 传 PR 号（`#1202`）或 commit sha，回执里的 `first_release` 是最早包含它的版本。
- **PR 还没合并**：工具会直接说不可能在任何版本里，这时就照这么说，不要再去猜"大概下个版本"。

## 三句不能说的话

- 「已经修复了」——除非拿到了包含它的**已发布版本号**。合入只能说"改动已合入，但还没有包含它的发布版本"。
- 「还没发布」——工具只比对了 `checked` 里那些版本。没找到就说**"在查过的这几个版本里没有"**，并把查过的列出来。
- 「升级到 xx 就好了」——除非那个版本确实存在且确实包含它。查不到对应版本的发布，就说查不到，别让人白等。

## 怎么组织回答

先给结论（进了 / 没进 / 查不到），再给版本号和链接，最后才是不确定的部分。对方正卡在这个问题上，不要把"我查了哪些"放在最前面。

同一个话题里别人问过的版本，回答时带上上次的结论有没有变；版本状态会变，"上次说没发"不代表现在还没发。

用户版本比修复版本旧时，说清楚**升到哪个版本**能解决，而不是笼统说"升级一下"。他不升级也可能有原因（预览版不敢上），这时给出临时可用的做法，不要只说"等发布"。
