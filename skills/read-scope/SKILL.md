# 我在私聊里能读到哪些

连接、申请范围、飞书实际授予的 scope、具体资料读取成功是四件事。只依据本轮工具返回的 `facts` 和读取结果说话；旧助手回复、技能说明、申请清单都不能证明当前授权，更不能证明全量可读。

连接请求用 `friday_connect_account`。宿主会发卡并交付确定性回执；`delivery.status=sent` 后不重复、改写或扩展授权承诺，继续用户同轮的其他工作。只处理连接时可不再发正文。返回 `not_sent` 不等于已发送；失败照实说明，不声称卡已发。

`facts.capabilities` 按实际 scope 标 `scopeGranted`，`requested` 仅表示申请；`resourceAccess=not_checked` 必须保持未知。基础授权含文档读写，不能说全部只读；群聊历史、日程、妙记各有附加授权，基础连接不能推导这些已启用。即使相关 scope 齐全，也只说明已授予对应范围，具体目标仍须访问权限、停读设置和实际读取结果。

GitHub 身份映射、仓库读取权限和指派关系独立核验。飞书 OAuth 不连接 GitHub，也不证明“我的 Issue/PR”能查到。查询正式事项用 `project-tracking`，取得可信 GitHub login 和当前获准仓库后再查，不凭飞书姓名猜。

他随时可以收窄：**跟我说一声就单独停读某个会话**（网关会把「关注的群聊」那张卡发出来，上面每个会话都有「停读」按钮）。

## 被停读时怎么办

工具会返回 403 并点名是哪个会话。这时：

1. **照实说**：「「管理层群」你之前让我停读了。**跟我说一声就能恢复**，恢复后我会**从上次读到的位置接着读**。」
2. **不换路径重试**：读历史被拒之后去搜索、去翻缓存、去找别人问，都是绕过他的决定。被拒就是被拒。
3. **不把"停读了"说成"没有"**：「我没搜到」和「这个会话我不看了」是两回事，混起来会让他以为群里真的没这件事。

## 不能替他决定

- 他说"别看 xx 群了" → 引导停读那**一个**，不要顺手把别的也停了。停一个只停这一个。
- 他问"你能看我哪些群" → 调 `friday_visible_groups`，**照它返回的说**；不要凭印象报一个数。
  区分返回的身份、列表覆盖范围与消息正文访问结果；可见会话列表不等于每个群历史都能读。缺授权时让网关发卡，**不要让他去敲命令**。
- 他还没授权 → 说清楚"你在、我不在"的那些群现在读不到，并让网关把**授权卡**发给他（卡上就有「打开授权页面」按钮）；不要假装读过，也不要让他去敲命令。

## 两件他常问的事

- **"我停掉的这几天消息还在吗"**：位置保留，恢复后接着读，**中间那段不会补发**。
- **"整个断开之后呢"**：不能再用这份个人身份读取；应用身份能否读取是独立权限，不能说一个群都读不到。他之前停读的记录**保留**，重新连接时那些还是不看。
