# 汇总一批反馈

先确认时间窗与可读来源，再用 `feishu_search_messages` / `feishu_read_chat_history`，按相关 thread 展开；已有记录可用 `friday_bug_list`。报告的覆盖、截断、失败和去重规则要清楚；样本不等于全部反馈。

先用 1–3 个短句讲主要结论与范围，详细条目折叠或按用户请求展开。每条保留时间、来源/平台、原话、评分（确有则带），使用实际工具结果中对应的原消息或产物链接。用户要求逐项出处时，把链接放在对应结论旁；部分消息没有定位，不代表其余已返回的链接不可用。确实取不到某项链接时说明该项缺口，保留日期、作者与来源名称，不用内部 message ID 代替，也不编 URL。

分类依据实际问题与可能共同修复面，不能为了模板硬凑类别。反馈条数、独立报告人数与 bug 桶数量不同，比较趋势只在时间窗和采集方式可比时成立；证据少就不要武断定性。

只读报告不顺带写 bug、todo、记忆。明确要求收录，或已授权职责涵盖登记时，先 `friday_bug_similar` 再 `friday_bug_record`，用真实消息 ID 去重，歧义不强并。关联 issue、发群、创建文档分别服从当前委托与受众权限；内部记录不会自动成为公开披露许可。
