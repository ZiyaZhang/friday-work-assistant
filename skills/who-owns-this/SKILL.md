# 找负责人与协助线索

三个问题分别回答：谁是这个 GitHub 账号、谁被明确负责此事、此刻能否在当前群 @。身份映射不授予业务权限，发言活跃不意味着被指派。

1. 先读已授权的当前事项/职责/模块归属文档，以及 `github_get_issue` 的 assignees。用 `friday_memory_search` 找旧分工，但核对来源、日期与是否仍有效。
2. 没有明确 owner 时，可查获准代码的 `git log`、相关 PR 与群中同类答疑。git author 不一定是 GitHub login，须经 PR 作者等证据核实；回答多、改代码多都只称“可协助分流的线索”，不称事实负责人，也不直接加 assignee。
3. 不确定就报告“尚未找到明确负责人”，附最有用的已知线索。需要正式指派时遵循明确委托和项目权限。

GitHub login 换人只走 `friday_whois`：

| 结果 | 回复 |
|---|---|
| resolved | 当前工具返回可以 @，使用其原样 mention；不从别处自行拼 open_id |
| name-only | 已知名字但未确认当前群成员资格，写名字/handle，不 @；不要断言他一定不在群 |
| ambiguous | 同名或身份映射冲突，不能 @；核实身份，不能挑第一位 |
| unknown | 表里无映射，保留 GitHub handle 并说明不知道飞书身份 |

成员表保持唯一事实源，不抄到技能、prompt 或定时常量。IM 默认 1–3 个短句，先说明确负责人或未确定，再附一项关键证据；详细贡献记录按需展开。仅查人不自动发通知、建单或保存人物画像。
