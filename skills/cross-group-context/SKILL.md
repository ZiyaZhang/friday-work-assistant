# 跨群把同一件事接起来

一件事常常散在几个群：产品群改了需求、研发群在讨论实现、反馈群里用户在说结果。**本群的历史回答不了"这件事现在到哪了"。**

能不能读兄弟群，取决于这几个群**有没有结成联盟**：

- 结了：`feishu_read_chat_history` / `feishu_read_thread` 可以直接读兄弟群，回答末尾会自动带一行出处披露。
- 没结：只能读本群。想接起来就告诉用户 —— 让群负责人在任一群里跟我说一声，把相关的群加进同一个联盟（他说就行，不用记命令）。**不要自己绕**，也不要拿"我读不到"当结论就停在那儿。

`friday_visible_groups` 能看当前联盟里有哪些群。

## 什么时候该去读兄弟群

只在**本群信息不足以回答**时去读，而且要带着具体问题去，不是把兄弟群翻一遍：

- 本群在问"这个需求做了吗" → 去研发群找对应的实现讨论或 PR
- 本群报了个障 → 去反馈群看是不是同一个现象已经有人提过
- 本群要拍板 → 去产品群找当初的结论和它的前提

读之前先想清楚要找什么；找不到就说在兄弟群里也没找到，**不要把"没读到"讲成"没有"**。

## 三条边界

- **嘴留在本群**：读了兄弟群不代表可以去那边发言。要通知那边的人，得有明确委托。
- **出处会披露**：引用兄弟群内容时回答末尾自动带一行。不要在正文里再复述一遍，也不要因为怕暴露就把来源模糊掉。
- **受众不因联盟扩大**：兄弟群里的敏感内容不会因为"同联盟"就能在本群原文复述。拿不准就只给结论和链接，让有权限的人自己去看。

联盟是群和群之间的关系，**不是人的授权**。私聊里替某个人读他所在的群是另一回事，走 `watch-group-secretary`，那条要本人逐个授权。
