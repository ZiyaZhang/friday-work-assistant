# 继续处理已有 PR

用 `github_list_changes` 找回当前工作的修改目录与 PR，用 `github_pr_diff` 核对最新 head SHA、diff、评审和行内评论。登记列表是本地记录，不能当成远端实时状态。列表没有该 PR 时，不能另开 PR 冒充接续，也不能改 marker 转移归属；当前工具仅支持同会话、同发起人的登记修改，跨会话接续尚未开放。

按当前代码判断意见是否仍适用。评论的 commit_id 与当前 head 不同，表示它针对旧版本，先检查问题是否已经解决；行内评论存在不表示未解决的评审线程。coverage 显示读取失败或截断时，说明具体遗漏，已有可核实的部分可以继续处理。

在原目录落实用户要求及有效评审意见，运行仓库要求的相关检查。两条并列要求分别核对，例如“分批展开”与“展开后可收起”都应保留。不要把建议照单全收，也不要用口头解释代替要求的修改。

改完调用 `github_update_pr`，dir 为原目录，title/body 描述这一次提交与实际验证。工具只向同一 PR 追加提交，不改变原 PR 标题和正文。首次发布仍用 `github_open_pr`。

远端有新提交或 PR 已关闭时，保留本地成果并说明当前状态，不能覆盖他人提交、重开 PR 或另开副本绕过。更新结果未知时先核对原分支与 PR；同一次更新可通过原参数恢复核对，不换标题或修改文件重试。

回执一两句说明落实的意见、实际验证和原 PR 链接。只有返回确认的提交后才能说已更新；没有合并、发布证据时只报告提交结果。
