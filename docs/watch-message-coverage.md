# 关注群的消息覆盖与恢复

运行完成时间 `last_run_at` 仅用于执行统计；消息消费使用 `message_cursor_sec`。每次 watch 固定 `[cursor, 本轮开始秒]`；没有旧覆盖证明的职责从创建时间开始，不把历史成功状态推测成已读。

模型仍按现有 history 工具取群消息。网关从实际返回的分页元信息记录完整秒段，合并多页；关键词筛选、只读最后一页、有缺口的分页和只读部分群都不能证明完整覆盖。全部配置来源完整后，才允许本轮正常发出摘要或按约定静默。授权过期、失败、取消和覆盖不完整均保留读取起点。

投递仍用现有 occurrence 和 deliveries。完整读取窗口在外部 POST 前保存；真实 sent/confirmed 收据可恢复已处理水位，处理“发送已落账、游标尚未提交就退出”的窗口。planned/unknown 尚未核对时，不因新的 occurrence 换 key 重发。该元数据不是另一个任务系统，不重新执行旧模型会话。

此契约证明的是群消息流时间段，不证明所有话题、卡片和附件已展开。秒级边界可能重读；同秒消息过多且无法完整分页时失败并保留起点。迟到或平台事后修订的历史消息不属于本次覆盖保证。当前公开更新接口不支持修改关注群集合；以后提供此功能时必须明确重置新来源游标。

`test/routine-coverage.test.ts` 使用真实 MessageService、内部 API、Orchestrator 和 SQLite 加合成飞书/模型，覆盖正常多页、多来源空流、缺页、关键词、同秒截断、失败/取消、执行期间新消息、未知发送不重发及已发送窗口恢复。这些是自动化回归，不是线上长期巡查验收。
