# 最终回复的来源与发送状态

普通对话的最终答案现在按实际读到的网关来源检查受众。同群自产内容照常回复；本人私聊读取本人仍有访问权的群资料，仍可只回给本人。私聊发布前重新查询飞书群列表或成员，不使用这两类查询的缓存。

群间互读的 Circle 配置只授予读取权，没有定义把来源群资料转给另一群的披露许可。当前交互路径没有签发这种发布许可，所以包含跨群资料、或第三方文档/日历资料的群回复会被挡住，并给出简短说明。个人连接取得的文档/日历只允许回到连接所属人的私聊；当前仅复查连接有效，尚未逐资源重新查询 ACL。

来源按 ACP 会话累积，跨轮及网关重启保留，不受 `/why` 回执十条展示上限影响。已有 ACP 历史没有完整来源记录时，第一次继续会重建 ACP 会话历史；这不会清空工作目录。记录包含当前允许的记忆层，以及 API 实际返回的群、外部资料和仓库引用；不会保存资料正文。

含外部资料的会话暂不自动写 QA 记忆或做轮末整理。`canPersistDerivedState` 也提供给 API 写入口使用，阻止已知外部资料被改写成不带来源的本地状态。常规定时任务和主动巡检均从新 ACP 建立来源记录；主动巡检无用户身份，只通过自己的窄 token 行动，这个来源检查不会授予负责人权限。候选记忆合并使用另一套 `memoryWritePolicy` 候选集约束。

仓库资料也会阻止上述无来源派生写。`canPublishToRepository` 只为同一仓库的后续 Issue/PR 操作提供来源例外：本会话累计读过的每个仓库都必须等于目标仓库，同时聊天和文档来源检查仍须通过。读私库 A 后写 B 会拒绝，不能把“两个仓库都能读写”当作允许相互披露；读 A 后在 A 修 PR 仍需另过原有 scope、repo allowlist 与操作授权。旧清单没有仓库记录字段时按来源不完整处理。

## 具体发送账本

`DeliveryService` 的输入包括宿主提供的上下文引用、稳定效果 key 和正文。当前会话身份、空间、来源、受众与许可都由宿主 resolver 提供，不接收模型自报的来源证明。SQLite `deliveries` 存身份、受众、来源引用、正文摘要与远端回执，不存正文。

| 状态 | 意义 | 重试行为 |
| --- | --- | --- |
| `planned` | 已原子占位，可能正在发送 | 不再 POST；停机恢复后标为 `unknown` |
| `sent` | 远端 API 返回了消息 ID | 仅允许只读回验；不当作已回读确认 |
| `confirmed` | 只读验证了消息 ID、受众与正文摘要 | 相同效果 key 返回已有记录 |
| `unknown` | 请求或回执不确定，可能已经发出 | 不自动重发，等待只读对账 |

同一效果 key 不能用于不同身份、来源、受众或正文。发送失败后不会换一份错误正文盲目重试；明确的来源拒绝可以单独发送固定安全提示。缺身份、来源不全、空间停用/换绑、会话被打断时均拒绝。当前飞书最终回复适配器尚无独立回读 verifier，因此正常回执停在 `sent`，不会冒充 `confirmed`。

## 当前接线范围

- 已接入 `runTask` 的最终文本、卡片、分段回复；创建长答案文档前先检查来源。
- 入站 `message_id` 经持久 receipt 去重，在排队、插话和 ACK 前返回，网关重启也不会自动再次执行同一入站消息。
- 内部 API 绑定每次运行实例的 `runId` 和阶段 `stage`。同一个人后来在同一会话发起的新任务，也不能继承旧请求的确认结果。
- `recoverInterrupted` 只可在没有活动发送者的启动恢复阶段使用。`reconcile` 需要可信的只读远端 verifier，不提供自动重发接口。

这里没有把所有出站路径都接入账本：定时摘要、主动巡检通知、命令卡片等仍走已有发送路径；长答案文档的创建和分享也没有各自的效果账本。来源清单只覆盖接入的网关数据，不能追踪 DSH 原生文件/命令读取；同 Unix 用户可读网关数据库或密钥的问题仍需操作系统级隔离。共享记忆中历史内容的原始来源与晋升授权也不是本模块已经解决的能力。
