# D1：职责操作与状态查询

本片把现有职责控制从 Orchestrator 移到 `RoutineApplication`，并给现有查询增加可解释的运行状态。单进程、原 Routine/Occurrence/Run/Delivery 继续使用；不新增调度器或数据库表。

## 接口及归属

| 入口 | 应用操作 | 状态来源 |
| --- | --- | --- |
| 自然语言工具、命令、卡片 | `control(id, pause/resume/delete)` | RoutineStore、当前 Space 和个人授权 |
| 反馈停止、空间停用等既有宿主操作 | `stop(id, pause/remove)` | 同一职责及实际活动 Run |
| OAuth 网页、粘贴回调、完成授权按钮 | `authorizationCompleted(openId)` | 当前个人 token、职责暂停原因与当前空间绑定 |
| 已授权职责查询 | `routineProgress(store, routine)` | Routine、最新 Occurrence 的持久事实 |

真实调用者与对象管理权限仍由入口验证；服务接收宿主解析的编号和身份，不新增绕过权限的公共接口。未来后台必须复用入口授权及此应用操作，不能直接写表。

## 状态与副作用顺序

暂停或删除先在 SQLite 短事务中更新职责、取消 occurrence、登记对应 Run 的停止，再提交后 abort。原停止、权限和投递 guard 保持，迟到结果仍写原 Delivery；取消不声称撤销已发生的远端动作。

恢复核对当前空间状态、绑定和关注职责的个人连接，再使用现有 `resume`。曾开始执行的一次性职责不能直接重排；原编号、执行时间、游标保持。恢复授权只恢复 `AUTH_EXPIRED`，不恢复手动暂停、空间停用或其他原因。token 查询等待后再核对当前 token，避免断开期间的旧响应恢复职责。

查询返回运行身份、读到的消息时间、上次运行状态、下次计划、最近 occurrence 和下一步恢复类型。暂停或未接受提案的 `next_run_at=null`；仍保留 Routine 的原计划，不因此改时间。查询与实际恢复共用 `RoutineStore.resumeState`：已领取或运行中的一次性任务显示等待，已完成任务改到新的时间后可以恢复。查询不恢复、不补跑、不移动游标。模型执行成功不是外部产物交付成功，本片不把 `last_status=ok` 解释为已发消息或已写表格。

群列表读取失败与成功空列表分别显示。已有连接只说明可按当前权限查资料，不等于已委托关注所有群。

## 本片验收和边界

- 原自然语言/命令/API 控制、OAuth 恢复、执行中停止、一次性任务防重复继续回归。
- 新增真实 MCP → HTTP 查询断言：暂停职责显示原身份和游标，无下次运行；中断 occurrence 显示需核对且不能直接恢复；整条查询前后数据库状态不变。
- 群列表失败不显示“一个都没有”，成功空列表才这样显示。
- 本片没有 schema 变更；与 C1 同批时仍执行整个真实旧库保护升级，不以本片无迁移跳过。
- 自然语言质量和真实飞书效果另行验收。尚未实现完整 unknown 核对、后台页面、授权完成后的通用工作接续，也不把工程回归计作这些功能完成。

对应原功能：G09 职责、G10 群列表、G29 自然语言职责，S02 局部暂停、S03 授权恢复、S06 停止关注。其他 57 项状态不改变。
