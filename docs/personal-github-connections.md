# 个人 GitHub 连接：批次 A

此文记录实现和上线步骤。

## 用户流程

在 Friday 私聊打开「账号连接」，选择登录 GitHub 或使用个人令牌。回调核实账号后更新原卡，随后自动读取评审请求、指派的 Issue 和本人提交的 PR。GitHub 可以独立连接，不等待可选的日历授权。App 登录受本人权限与 App 安装范围共同限制；个人令牌按该令牌的实际权限读取，仍受组织审批、SSO 和令牌政策约束。

个人令牌在独立 HTTPS 配置页输入，页面使用一次性 RSA-OAEP 公钥在浏览器加密。公钥与十分钟有效的本人连接请求绑定并签名；Worker 只保存加密信封。私钥和最终令牌分别加密保存在服务端，不进入聊天、模型、URL 或日志。新令牌核验成功前保留旧连接。断开、换号、取消、过期和迟到回调均受授权版本控制。


首批结果只投递一次，飞书和 GitHub 复用同一份个人清单及送达记录。待处理事项在前；本人提交的 PR 放在折叠区，不把“本人提交”自动等同于“别人正等你做”。PR 和 Issue 名称可以直接打开网页，来源也可点击。勾选完成是用户纠正状态的快捷入口，不要求逐条作答。

后台核对 PR 合并、本人正式评审、Issue 完成与取消。GitHub 原生指派被移除时，从待处理清单移走；同一条飞书承诺不因指派人变化而自动结束。搜索没有返回某项不代表它已完成。手动完成、忽略和恢复优先，扫描不重新创建同一事项。

评审准备会核对当前提交，读取 PR、代码改动、检查与讨论；结合本人已授权飞书范围的相关讨论，交付评审要点。缺失的背景或权限要如实说明。准备结果与原待办分开，用户正式评审或 PR 合并才结束原事项。回复草稿只交付给本人。本批不向 GitHub 写代码、发评论或代发飞书消息；这些操作不会转用部署账号。

## 权限与运行

- 用户授权使用 GitHub App 的 Client ID / Client secret，OAuth state 绑定飞书本人，带过期时间和 PKCE。
- Cloudflare 仅保存加密的临时回调；客户端 secret 与用户 token 留在服务端。数据库里的用户 token 和 PKCE verifier 加密，密钥位于数据库旁的 `connection.key`，首次生成权限为 0600。备份密钥与数据库分别管理。
- 请求级 GitHub 客户端、后台收集和工作执行都绑定本人及授权版本。撤销、账号切换或失效使旧请求结果作废；刷新 token 使用单路刷新，避免并发消耗同一 refresh token。
- 私聊的仓库来源记录授权版本，历史部署身份读取的数据不会因为填写用户名而获得新权限。群聊仍受既有团队身份和权限约束。
- 断开会删除 Friday 持有的 token，停止读取；已记事项保留。要撤销 GitHub 上的 App 授权，可在 GitHub 设置中撤销。该动作与取消 App 安装不同。
- 临时迁移通路由宿主运维显式开启：必须核实已有部署凭据与本人已连接 GitHub 的账号 ID 和登录名一致，列出确切仓库，最多七天到期；只有 GET 和三类仓库限定的事项搜索可使用。其他人不会自动获得这条通路。开启、停止、到期都使旧授权版本失效；连接卡展示范围、到期时间和停止入口。
- 扫描间隔目标 5 分钟；每轮最多 3 位用户、每人 3 类搜索、每类最多 50 条。结果超限会标明部分读取；目前尚无完整分页回补，不能宣称覆盖所有 GitHub 事项。飞书历史收集沿用原有增量及断点机制。

## 上线配置

1. 复用 Friday GitHub App，在用户授权回调列表添加 `https://<OAuth relay host>/github/callback`。GitHub App Client ID 与 App ID 不同。
2. 设置 `FRIDAY_GITHUB_CLIENT_ID`、`FRIDAY_GITHUB_CLIENT_SECRET`。可选设置 `FRIDAY_GITHUB_APP_SLUG` 提供选择仓库按钮。团队 PAT、App 私钥与 relay 凭据保持独立。
3. Secret 由管理员在本人终端输入：`python3 scripts/configure-github-personal.py --host <ssh-host> --client-id <app-client-id>`。不从聊天、命令行参数、日志接收 secret。脚本仅更新服务端 `~/friday/.env` 两项，原子写入且权限 0600，不主动重启。
4. 部署 `cloudflare/friday-oauth`，其已有飞书回调与新增 GitHub 回调分别校验 provider，原 D1 结构兼容。验证旧备份和实时数据库副本升级后，再部署 Friday 服务。
5. 未配置 Client secret 时不能进行 App 登录；已配置 HTTPS relay 时仍可使用个人令牌。没有本人显式迁移授权，不会使用部署账号兜底。

## 验收与剩余范围

代码测试覆盖真实 HTTP 路由的双用户隔离、用户名不能授权、断开后的并发响应、OAuth 过期/重放/换号、加密和刷新、扫描去重与忽略保持、首卡投递复用，以及真实宿主执行中的断开取消和结果抑制。

上线必须再核实真实浏览器 OAuth、App 安装范围、飞书实际渲染与点击、首批真实事项、模型实际交付。两个普通账号拥有不重叠私有仓库的验收仍需真实账号参与；模拟双用户测试不能替代它。当前 App 若没有 Actions / Checks 读取权限，评审产出须注明无法读取的检查详情。

尚未在本批实现：邮箱、个人自定义 MCP、个人 GitHub 写入、草稿跨端版本与发送回执、DSH 第二入口、早报时区编辑、所有 GitHub 搜索结果的分页回补。
