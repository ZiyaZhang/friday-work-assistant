# Signal 层与主动式

> 状态：设计已定，实现中
> 前身：把"安静够久 + 攒够 N 条消息就去看一眼"换成"有信息进来才判断"
> 设计范围：信号分档、退避、反例、聚类、去重与阈值核对。

---

## 0. 一句话

**主动不是定时去猜，是有东西进来了才判断；判断完也不立刻说话，要先聚类、去重、对阈值。**

这一层的目标不是每条消息都警觉一次，而是——**该升级的一定升级，不必要的噪音不会被重复打扰**。

## 1. 为什么要单独一层

现在的主动模式是这样触发的：群里安静了 `quietMs`，且这段时间攒了 ≥ `minMessages` 条新消息 → 起一轮模型会话，把这批消息喂进去问"有没有该接的"。

三个问题：

1. **"安静"不是信息。** 大家下班了也安静，讨论结束了也安静。用安静当触发器，等于定时去猜。
2. **同一件事会被重复触发。** 同一个问题在三个群里被问，我们会在三个群各自判断、各自回一次。三次都"对"，合起来是错的。
3. **没有退避。** 一件事该提醒几次、隔多久、第几次之后闭嘴，全无规定。

Signal 层把"什么东西进来了"和"要不要说话"拆开：进来的东西先归一化成信号入库，聚类去重之后再对阈值，够了才起模型。

## 2. 信号

### 2.1 归一化 schema

所有入站来源（飞书消息、GitHub webhook、CI、定时职责的产出、以后的 screenpipe/CUA）统一成同一种结构：

| 字段 | 说明 |
| --- | --- |
| `kind` | 信号类型，决定用哪套阈值。见 2.2 |
| `source` | 从哪来，如 `feishu:oc_xxx`、`github:org/repo` |
| `spaceId` | 归属空间。**信号永远属于某一个空间**，跨空间不合并 |
| `fingerprint` | 同一件事的指纹。聚类与去重全靠它 |
| `payload` | 原始载荷（JSON），起模型那一轮才展开 |
| `title` | 一句话，给人看的 |
| `firstSeenAt` / `lastSeenAt` | 第一次/最近一次看到 |
| `count` | 同指纹合并了几次 |
| `status` | `open` / `escalated` / `resolved` / `muted` / `expired` |
| `alerts` / `nextAlertAt` | 退避状态 |

**指纹怎么算**：小写、去标点空白之后取 sha1 前 16 位。同一个问题换个说法就不是同一个指纹——这是有意的，宁可漏合并，不要错合并。

### 2.2 信号类型与阈值

| kind | 什么时候产生 | 阈值（满足才升级） | 证据档 |
| --- | --- | --- | --- |
| `unanswered_question` | 群里有人问了一句像问题的话 | 存活 ≥ 10 分钟且这期间没有别人在同一话题里说话 | 弱 |
| `mentioned_stalled` | 有人 @ 了某个人，那个人没回 | 存活 ≥ 4 小时 | 弱 |
| `task_overdue` | 待办过了截止时间 | 立即 | 强 |
| `external_failed` | CI / 构建 / 部署失败（webhook） | 立即 | 强 |
| `duplicate_burst` | 同一指纹在 ≤ 30 分钟内出现 ≥ 3 次 | 立即，且**合并成一条**，不逐条报 | 强 |
| `responsibility_conflict` | 自检发现两条职责产出重复 | 立即 | 强 |

**弱证据必须叠加会话上下文才升级。** 借 watchdog spec 里 Path C 的思路："shell prompt 空闲很久"本身没意义，"刚才在跑 AI、现在回到了 prompt"才有意义。对应到这里：群里没人说话没意义，"有人提了个问题、十分钟没人接"才有意义。

### 2.3 聚类与去重

信号进来先按 `(spaceId, kind, fingerprint)` 找已有的 `open` 信号：

- 找到 → `count += 1`，`lastSeenAt` 前移，**不新建**。
- `count` 达到 `duplicate_burst` 的门槛 → 额外产生一条 `duplicate_burst`，原信号标记为已被它代表。
- 找不到 → 新建。

跨空间**不合并**，但升级时会把"同指纹在别的空间也出现过 N 次"作为上下文带进提示词（只带计数，不带别人群里的原文——跨空间披露仍然要过 Policy）。

### 2.4 反例：绝不升级的情况

先写这张表，再写触发条件。

| 场景 | 判定 | 理由 |
| --- | --- | --- |
| 发信号的人自己随后又说话了 | 同一话题里同一人 30 分钟内有新消息 | 他自己在处理 |
| 有别人接话了 | 同话题里出现了非发起人的消息 | 已经有人管了 |
| 空间的主动模式没开 | `proactive.enabled === false` | 人没要 |
| 这一小时配额用完了 | `quotaLeft <= 0` | 抑噪 |
| 信号在退避期 | `now < nextAlertAt` | 见 2.5 |
| 信号被人明确关掉过 | 同 `(spaceId, kind)` 有 `muted` 记录 | 人说过不要了 |
| 空间处于降级（授权过期） | 见 §4 | 没有有效身份，宁可不动 |
| 机器人自己产生的消息 | `senderOpenId === botOpenId` 或 `senderType === 'app'` | 不自己跟自己聊 |

### 2.5 退避

按 `(spaceId, kind, fingerprint)` 三元组：

```
第 1 次：通过阈值后立即
第 2 次：上一次 +60s
第 3 次：上一次 +5min
第 4 次：上一次 +30min
第 5 次起：不再说话，状态转成 muted，只留一条记录进 /status
```

退避状态在信号被 `resolved`（有人接了 / 待办完成 / CI 转绿）后清空。

这条直接回应"一件事它每分钟戳我一次"——指数退避之后进降级通道，从打扰变成一个可查的观察项，什么时候处理由人决定。

## 3. 升级：从信号到一轮工作

到阈值的信号进入 `escalate`：

1. 同一空间同一轮的多条信号**打包成一轮**，不是一条起一轮。
2. 起一个只读会话（`PROACTIVE_SCOPES`），提示词里带：信号列表、每条的 `title` 与出处、`count`、跨空间同指纹计数。
3. 模型只能产出两种结果：一句要发的话，或 `NOTHING`。
4. **发之前过一道纯代码的闸**（不经模型）：长度上限、不许 @ 人、不许含别的空间的原文、配额内、不在退避期。权限由宿主能力边界约束，不依赖提示词自觉。
5. 发出去的卡片**必须带触发出处**：`因为 9/12 有人问了 X，10 分钟没人接`。人一眼知道它为什么冒出来，误报也好纠正。

## 4. 降级：授权过期按委托人暂停

委托授权（user token）过期时：

- 暂停使用该用户授权的关注职责；其他用户的职责不受影响。
- 保留读取游标。重新授权后按当前权限和平台仍可提供的历史继续读取，不承诺历史完整。
- 网页回调、粘贴回调和“完成授权”按钮共用恢复操作。仅恢复授权到期且所属空间仍启用、绑定未变的关注职责；手动停用和空间停用不被重新授权覆盖。
- 授权卡发给委托人，说明受影响的是这份授权下的关注任务；回执只报告实际恢复数量。

## 5. 关停：自然语言，且说清连带影响

"别盯这个群了" / "停止关注" / `/proactive off` 都要走同一条路径，回答里必须包含：

1. 关掉的是什么（这个空间的主动巡检）
2. **连带停掉了哪些职责**（列名字）
3. **历史数据还在哪**（看板链接 / wiki 链接）
4. **当前还在盯的是哪些**

关停按 `(spaceId)` 或 `(spaceId, kind)` 粒度，写成 `muted` 记录，不是删数据。

## 6. 红线

- **没有新信息就不说话。** 定时器只负责"看有没有攒下的信号到阈值了"，永远不负责"到点去猜"。
- **信号永远属于一个空间**，跨空间只传计数，不传原文。
- **主动会话永远只读。** 需要写的事只能提议，不能自己做。
- **人在说话时不插嘴。** 有人正在同一话题里发言，一律不升级。
- **原始载荷不出机器。** 以后接 screenpipe，帧在本机 OCR、本机过规则，出去的只有一条信号，不是截图、不是 OCR 全文。

## 7. 和现有模块的关系

- `proactive.ts` 保留：它管的是**配额、休眠、每空间节奏**，不再管触发。
- `signals.ts` 新增：归一化、聚类去重、阈值、退避、关停。
- `orchestrator.runProactiveCheck` 改签名：从"给一个 chatId 去看看"变成"给一批已经到阈值的信号，去处理"。
- 定时器（60s）改成 `sweepSignals()`：取到期信号 → 按空间分组 → 每组一轮。
