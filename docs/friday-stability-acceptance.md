# Friday 稳定性与真实流程验收

此文档记录验收方法与代码入口。自动测试通过不代表双账号三天试用完成，平台权限不足也不能写成同步成功。

## 聊天

DSH 首次请求 `conversation(includeResults:false)`，先显示本人主会话的最近消息、送达与执行状态。最新三条回复并发两路单独读取，其余由用户展开。正文每次读取保留原始来源权限核验；元数据不延长正文的授权展示期限。正文超过 30 秒未成功复核就收起，账号/主会话变化或断网时失效，迟到结果不能回填到新会话。旧网关仅在明确不支持新字段时回退原接口。

后台每 15 秒更新元数据；失败后从 3 秒逐步退避到 60 秒，回到页面或恢复联网立即尝试同步。消息发送失败保留原 requestId，用户重试相同消息不新建重复工作。用户主动再次发送相同文字则生成新 requestId。

网关最多并行准备 4 个桌面请求；来源读取不再占住下一轮 relay 轮询。SQLite 提交及副作用交接保持同步，设备撤销、停机与重复请求仍检查原身份和回执。

入口：`integrations/dsh/lib/client.js`、`src/personal/desktop-application.ts`、`src/personal/desktop-bridge.ts`、`src/personal/results.ts`。

## 我的事项与飞书任务

事项来源和准备工作沿用本人的来源快照，准备结果不自动完成事项。确认完成后由已有事项状态与同步回执记录更新；再次看到同一来源不能重新创建已忽略/完成事项。

原生任务仅同步 Friday 管理的任务，并非读取用户全部飞书任务。页面区分本地保存、等待同步、权限不足、结果待核对、已核验同步；更新时间使用最近一次成功读取时间，不将失败重试时间当作同步成功。缺少应用权限时持久化按能力退避，重启不能清空权限阻塞后再次集中请求。

缺少 `task:task:write`/`task:task:writeonly` 必须由应用管理员在飞书开放平台授权并发布。个人重新登录不能补齐应用权限。修复代码可以说明原因并恢复重试，不能替平台批准权限。

入口：`src/core/personal-assistance.ts`、`src/core/personal-collection.ts`、`src/core/feishu-task-sync.ts`。

## 本次发现

真实检查发现，同一讨论中的请求和认领可能被收成两项。当前去重依赖原消息证据或已有事项编号；本次两项没有明确的 `parentId` 引用关系。同话题、相近位置和近似标题不是可靠的事项身份，不能据此自动合并。这类重复仍是三天试用中的待解决项，不记为已修复。后续合并须有可核验的明确证据；证据不足时只提供合并建议，由本人确认，保留原事项和可撤销记录。

群聊和私聊的覆盖进度也可能不同：本次确认已解散群的消息详情无法读取，曾阻塞群聊后续窗口，私聊仍继续推进。现在仅对明确匹配这一原因的来源记录持久读取缺口，并继续收集可读消息；其他失败仍保留原窗口重试。页面分别显示两类来源的扫描进度、完整覆盖时间及缺口或重试状态；完整覆盖 `through` 不越过最早缺口，不能将扫描完成称为完整同步。缺口不存正文或原始错误，只有以后真实读取成功才清除；本人排除来源后该缺口不计入当前范围，恢复来源后重新计入。

后续去重验收补充四类回归：

- 明确引用：同本人、同会话、同类型且引用消息仅对应一项时，验证同批正序/逆序及跨页证据归入同一项。
- 合并边界：跨账号、跨会话、不同交付对象或一条引用包含多项工作时不得误合并；同条原文中的两项独立交付仍保留。
- 状态保留：补充或历史证据不能复活已完成、取消、忽略或删除的事项，也不能覆盖本人修改。
- 无明确引用：近似标题不自动合并；本人确认前状态不变，确认后证据可追溯、操作可撤销，重复确认不产生第二次变更。

## 外部能力

个人 MCP 的调用登记、人工确认、执行结果是同一回执；DSH 的单次等待超时不取消原确认。超过 60 秒后的允许、拒绝、运行中断与重启后不确定状态分别验收。读取公开仓库的快速确认成功不能代替延迟确认成功。

本机文件任务在单独临时目录创建测试输入，通过真实 DSH 工具读入、写出，再核对文件与回传。模型口头声称已写文件不算通过。

Gmail 使用本人测试邮箱。先完成只读授权，读取一封指定测试邮件；准备包含明确收件人、标题、正文的草稿；本人授权发送能力并确认该草稿后发送；使用实际邮件回执和已发送目录核对。真正向 Gmail 发出 send 请求前的 token/网络失败保持草稿；发出后未取得可靠回执保持 uncertain，仅核对，不自动重发。

入口：`src/personal/mcp-connections.ts`、`integrations/dsh/lib/local-runner.js`、`src/gmail/connection.ts`、`src/gmail/drafts.ts`。

## 两账号、三个工作日

待确定第二位试用者以及其本人已授权的账号。两个账号分别在自己的飞书私聊/DSH连接中操作；不能共享设备密钥或替另一人批准授权。未实际经过三个工作日，不填写完成日期。

| 每日检查 | 两个账号各自执行 | 记录 |
|---|---|---|
| 收集准确性 | 人工核对至少5条应收/不应收真实事项 | 应收数、实收数、误收、漏项、原因 |
| 准备与确认 | 选择2条事项准备，查看来源和结果，再由本人确认完成 | 原事项ID、准备taskId、完成时间、原生回执 |
| 重复与回流 | 重复读取原消息；第二/三天复查前日已完成和忽略项 | 是否重复/重现，不把新事项误当重复 |
| 范围与隔离 | A撤销一个已授权来源；B尝试读取A的测试事项 | 撤销后结果不可读、跨账号拒绝 |
| 聊天恢复 | 首次打开、后台更新、断网后恢复、同请求重试 | 首屏/正文/送达耗时、是否重复执行 |
| 原生同步 | 核对来源链接、覆盖范围、最近成功时间与真实状态 | 平台权限不足记阻塞，不计成功 |

每次记录实际运行 SHA、账号代号、日期、操作、截图/回执、判定；默认只保留代号与合成标记，不复制私人聊天内容。验收门槛：零跨账号泄露、零未确认外发、零重复副作用、已确认完成事项零无证据回流；误收与漏项必须逐条解释后决定是否可发布为稳定能力。
