# Gmail 个人连接与邮件草稿

## 交付范围

每位用户连接自己的 Gmail。初次仅申请身份和邮件读取；发送权限在本人选择“允许发送邮件”后单独申请。未配置 Google OAuth 时隐藏入口和邮件工具，不影响已有来源。

后台从最近 7 天的收件箱增量整理待回复邮件，并继续检查之前仍未结束的话题。促销、社交、垃圾箱和草稿默认不进入首次扫描；搜索工具可由本人明确查询其他范围。分页、失败和最近完整检查时间独立保存，不能把一次读取说成全邮箱已检查。未读不等于待办，自己发过邮件不等于整个事项完成。

草稿保存在 Friday，可以在对话里修改同一份草稿。卡片提供修改、发送、丢弃，短邮件支持卡片表单，超过飞书输入框 1,000 字限制的正文继续在对话里修改。只有本人操作发送卡才发送；工具没有发送入口。发送前重新核实材料访问权、邮箱账号、草稿版本和原话题的最后一封邮件。

发出后保存 Gmail 回执并提供原邮件链接。超时和重启后只核对回执，不自动重发。发送成功不代表任务完成；后续扫描结合新回信更新待回复或等待反馈状态。

## 部署

1. Google Cloud 项目启用 Gmail API，配置 OAuth 品牌、支持邮箱、受众和联系邮箱。
2. 建立 Web application OAuth client。回调为 `https://<OAuth relay>/gmail/callback`，与服务端配置严格一致。
3. 请求范围为 `openid`、`email`、`https://www.googleapis.com/auth/gmail.readonly`，发送时再补充 `https://www.googleapis.com/auth/gmail.send`。没有申请邮箱删除、标签管理或修改权限。
4. 用 `scripts/configure-google-personal.py --host <host> --client-id <public-client-id>` 隐藏输入客户端密钥；重启前确认 OAuth relay 已部署 Gmail 回调。环境变量见 `.env.example`。
5. 测试模式加入实际验收账号。普通用户开放须完成 Google 对相应范围的验证；开发项目和测试账号跑通不能替代公开发布验证。

连接凭据在数据库中按用户和用途加密，密钥使用数据库旁的 `connection.key`。两者分开备份并限制服务账号读取。断开连接删除可用凭据、邮箱缓存和读取位置；已有草稿保留，但只有重新连接原 Google 账号才能查看。切换邮箱不会把旧草稿带给新账号。

## 已验证与待验收

本地自动化覆盖 OAuth 一次性回调、并发刷新、授权撤销、两个用户隔离、邮件证据分类、分页恢复、草稿版本、原邮件新回复、重复发送防护、回执核对和宿主来源检查。生产飞书 CardKit 已接受草稿卡和编辑表单的结构。

上述不等于用户实机验收。仍需在实际账号完成连接、首批邮件展示、起草、修改、明确批准的测试发送、回信更新、断开重连。Google 项目验证、普通用户连接和移动端布局要分别记录结果。部署和验收证据放在本轮 evidence 目录，避免把历史记录当作当前在线状态。
