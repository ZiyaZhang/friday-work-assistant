# 个人 MCP：确认与调用回执

个人 MCP 由 Friday 服务端代理，连接和凭据按本人隔离。DSH「Friday → 连接」添加 Streamable HTTP 服务后，在 Friday 主对话里直接描述要做的事。工具说明属于外部数据，不能代替用户委托。

只有本人明确选中的只读工具可以自动调用；其余调用会在本人飞书私聊发确认卡。卡片展示服务地址、工具名和完整参数，仅原私聊本人在原卡上的决定生效。即使服务端使用 `auto` 策略，这项本人确认也不会跳过。超出卡片可展示上限时拒绝本次操作，不截断参数后让用户确认。

## 为什么不再受 60 秒工具等待限制

旧路径把远端目录检查、飞书人工确认和实际执行放在同一个 MCP 请求里。DSH 的 MCP 客户端约 60 秒超时后取消 HTTP 请求，也会取消还在等待的确认卡；增加飞书确认超时不能解决这个问题。

现在先把调用登记到 SQLite，再立即返回调用 ID。`friday_wait_connected_tool` 每次最多等待 20 秒，始终读取同一次调用。结束某个等待请求不会取消原操作；用户停止原任务、撤销连接、改变权限或服务关闭则仍会取消。飞书确认保留原来的配置时限，默认 10 分钟。

如果模型先回复“正在等确认”并结束当前生成，宿主保留同一个 Run 和原卡；操作结束后在同一 ACP session 提醒模型读取回执。最多提醒两次；没有读到回执就标记部分完成，不发布完成声明。此机制不提供跨任务、跨服务重启的自动续跑。

## 执行与权限边界

- 同一本人、Run、连接版本、工具和参数只登记一次；JSON 对象键顺序不同仍沿用原调用。数组顺序保留。
- 参数来源和 MCP 连接在登记时一起固定；确认前、确认后、执行前和返回结果时重新检查当前授权。确认后还会重新核对远端工具目录，避免用户确认期间工具定义改变。
- 调用尚未发出时取消，状态为 `cancelled`。已发出但回执丢失或执行期间取消，保守标记 `uncertain`，不自动重试。
- 重启后，待确认调用取消；没有完整执行回执的调用标记 `uncertain`。查看历史只返回状态等元数据；结果正文仅由原运行在来源权限有效时读取，最终交付内容在原工作中查看。
- 等待接口需要本人当前任务的读取权限，不能通过传入其他人的调用 ID 或旧 Run ID 取结果。原操作仍保留发起时的执行权限和资料来源检查。

## 代码入口

| 位置 | 职责 |
| --- | --- |
| `src/personal/mcp-connections.ts` | 连接凭据加密、调用登记、去重、状态、等待及取消 |
| `src/personal/mcp-transport.ts` | 远程 MCP 传输与受限公网请求 |
| `src/internal/personal-mcp-routes.ts` | 本人任务准入、来源固定、发起与等待 API |
| `src/mcp/personal-tools.ts` | 模型侧工具目录、调用及等待工具 |
| `src/core/orchestrator.ts` | 原 Run 生命周期、确认卡、完成后读取回执 |
| `src/feishu/cards.ts` | 完整参数与本人确认卡渲染 |
| `integrations/dsh/lib/client.js` | DSH 连接和历史状态展示 |

确定性回归位于 `test/personal-mcp*.test.ts`，覆盖真实 MCP SDK 和签名 HTTP 协议，但外部服务、模型和飞书网络使用替身。真实 DSH、飞书人工点击与外部 MCP 验收需另行记录，不能以单元测试或健康检查代替。
