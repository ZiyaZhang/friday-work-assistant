## 第一部分：Friday 是什么

### 一句话

Friday 是一个飞书机器人。把它拉进群，它就是这个群的 AI 同事；私聊它，它就是你一个人的助理。
**每一个群、每一个私聊都是一个独立的空间**，配置、记忆、职责互不相通。

### 它能干什么

**群聊里（团队共用一个）**

| | 能力 |
| --- | --- |
| **技术客服兼工程师** | 报障查重、补问、建 Issue、指派；是缺陷就自己改代码提 PR |
| **项目经理** | 跟进进度、同步进度表、定时提醒当日任务与风险 |
| **团队助理** | 长讨论后总结结论与待办；定时巡查群，整理进文档或表格 |
| **产品设计师** | 方案有分歧时对比分析，直接产出**可点击的原型** |
| **发布助手** | 「这个修复进哪个版本了」——**合入不等于发布** |
| **新人导览** | 讲清这个群在做什么、有哪些核心资料、该找谁 |
| **不 @ 也出手** | 讨论安静下来，看一眼有没有没人答的问题能接 |
| **跨群串同一件事** | 结成联盟的群之间互相可读 |

**私聊里（每个人一套）**

| | 能力 |
| --- | --- |
| **问答搭档** | 问答、写作、资料整理 |
| **历史检索** | 翻两周前的资料、继续往前翻、把原文件发给你 |
| **读一个链接** | 本条消息中你明确提供的完整网页 URL；不改参数、不跨源跳转。链接不代表公开，结果仅用于本次原群或原私聊，跨轮需重新提供 |
| **记忆** | 记住 / 纠正 / 忘掉，每条都能查到来源 |
| **待办助手** | 自动盯住群里派给你的事，到期**私聊**提醒你本人 |
| **盯群秘书** | 帮你盯你在的任意群（它不在也行） |
| **我的一天** | 日历 + 待办 + 等你拍板的事 |

### 它能看见什么（一句话记住边界）

> **眼睛经授权可以看别的群；嘴和手永远留在本空间。**

就算你授权它读了十个群，它也只会在**当前这个群**里说话、做事。
读到的内容只回到发起的那个会话，不会被带到别处去。

## 第二部分：设计哲学

### 2.1 三个设计目标

| 目标 | 要解决的问题 | Friday 的设计 |
| --- | --- | --- |
| **空间隔离** | 一个群 / 一个人各有一套隔离的助手，带授权、职责、记忆 | 按空间管理授权、职责与记忆 |
| **团队协作** | 团队在 IM 里**共用**一个能写代码的同事 | 在群内委托代码工作，在原话题交付 |
| **组织上下文** | 独立的组织身份，跨多个群串联同一件事 | 经授权的跨群连接（联盟）与组织上下文 |

共同前提：**AI 要进到人已经在的地方去**，而不是让人再开一个新窗口。

### 2.2 取舍一：一个空间一个同事，而不是一堆 agent 互相传话

多智能体协作需要解决**共享状态怎么流转**。当分诊、诊断和对外发送分别由不同权限的主体承担时，
应明确共享状态以及各执行主体的权限边界。是否拆分，取决于实际工作和隔离要求。

Friday 当前侧重以下场景：

- 群里的事大多是**一件事从头到尾**：有人报个问题 → 查重 → 补问 → 建单 → 改代码 → 回话。
  拆成三个 agent 之后，每次交接都要重新解释上下文，**交接本身成了最大的损耗**。
- 真正难的不是"下一步该谁做"，而是**"这句话能说给谁听"**。
  读到的东西能不能发出去、发给谁、算谁的授权——这才是会出事的地方。

```
                     一个空间 = 一个同事
   ┌──────────────────────────────────────────────────┐
   │  空间（群 oc_xxx 或 私聊 ou_xxx）                  │
   │                                                    │
   │   ┌──────────┐   按需加载   ┌──────────────────┐  │
   │   │ 一个模型  │ ───────────▶ │ 21 个 skill       │  │
   │   │  执行者   │ ◀─────────── │ （只读需要的那个）│  │
   │   └────┬─────┘              └──────────────────┘  │
   │        │ 每次调用都带一张 capability                │
   │        ▼                                           │
   │   ┌─────────────────────────────────────────────┐ │
   │   │ 网关内部 API（工具的唯一入口）               │ │
   │   │  · 受众在发起那一刻就锁死                     │ │
   │   │  · 每个 await 之后重新验一次权限              │ │
   │   └─────────────────────────────────────────────┘ │
   │                                                    │
   │   记忆 / 职责 / 待办 / 游标 —— 都只属于这个空间     │
   └──────────────────────────────────────────────────┘
```

**不是"没有多 agent"，而是把多 agent 换成了"一个执行者 + 按需加载的 skill + 硬边界"。**

**这个判断什么时候会失效**，也写明白：当"产出结论"和"有权对外发言"必须是两个不同主体时
（比如合规审核外发），就需要分离执行主体，并在运行环境中落实权限隔离。
Friday 现在用「**确认卡 + 受众锁定**」覆盖这一类——需要别人点头的动作会生成一张卡，
@ 到该拍板的人，他不点就不执行。这条路能走多远还在看。

### 2.3 取舍二：权限用能力切，不靠提示词自觉

> 凡是能用"能力边界"直接切掉的，就不要写进提示词里。
> 提示词里的约束要靠模型自觉，长上下文一冲就可能失效；"它根本没有这个工具"是模型绕不过去的。

每一次工具调用都要出示一张 **capability**：哪个会话、谁发起、哪一轮执行、能做哪些事、什么时候过期。

三套预置能力集（共 28 项 scope）：

| 能力集 | 给谁 | 关键差别 |
| --- | --- | --- |
| `ALL_SCOPES`（28 项） | 私聊会话 | 含 `chat:read-others`（读发起人也在的别的群）、`calendar:read`；本人持久偏好另用 `profile:write` |
| `GROUP_SCOPES` | 群会话 | **去掉跨群读和读日历**——回答是全群可见的 |
| `PROACTIVE_SCOPES` | 没人 @ 的主动巡检 | 只读评估；不登记待办、记忆或反馈。回复由宿主另查当前委托、资料来源和发送账本；明确执行请求进入新的交互任务 |

最后一行是关键：**没人叫它的时候，它能做的事严格少于被叫的时候**。

工程细节，写在这里是因为它救过命：**权限在每一个 `await` 之后都要重新验一次**。
一个动作跨好几次网络往返，中途这个人可能已被移出群、空间可能已停用、这一轮可能已被叫停。

### 2.4 取舍三：读和说分开

```
   ┌─────────────┐                    ┌─────────────┐
   │   A 群       │                    │   B 群       │
   │  眼睛 ──────┼──── 经授权 ───────▶│  （读历史）  │
   │  嘴 ✋ ──────┼──── 永远不过去 ──X │             │
   │  手 ✋ ──────┼──── 永远不过去 ──X │             │
   └─────────────┘                    └─────────────┘
         └──▶ 读到的内容，只回到发起的这个会话
```

- **群里**：默认只读本群。要读兄弟群，先把这几个群结成**联盟**（需要负责人点头）。
- **私聊里**：连接个人身份后，用**你自己的权限**读你在的群（它不在也行）、单聊、有权限的文档。
- **无论哪种**：读到的内容不会被带进别的群，也不写成本空间之外的长期记忆。
- **引用了别处内容，回答末尾有一行披露**，告诉在场的人来源是哪几个会话。

### 2.5 取舍四：默认全开，可以逐个停读

个人授权这一层做过两版，最后推翻了第一版：

| | 第一版（已废弃） | 现在 |
| --- | --- | --- |
| 默认 | 一个群都不给，逐个勾选 | **全开** |
| 你要做的 | 先勾一遍群才能用 | 直接用；不想让它看的**单独停掉** |
| 为什么改 | "最小授权"很正确，但要先勾一遍群才能问"我上周在哪个群说过 xx"——这条路没人走完 | 使用成本压倒形式上的正确 |

配套三条义务：授权卡把范围说清楚 · **停一个只停这一个** · **恢复从上次位置接着读**（中间不补发，也不假装"消息不会丢"）。

`/disconnect` 整个断开，**停读记录保留**——重新连接时之前不想让它看的还是不看。

### 2.6 取舍五：命令不是答案

有一套斜杠命令，但它们是**快捷方式，不是说明书**。

大部分人不知道有斜杠命令，让人去敲命令就是劝退点。

所以定了一条规则，并且**让构建强制执行**：

> 除了命令表和帮助卡本身，任何发给人看的字里都不许出现 `/命令`。

被挡住时只有两条出路：**有界面就给界面**（缺授权就把能点的卡发过去）· **没界面就说人话**（"跟我说一声就行"）。

例外只有两个，写在代码里而不是白名单里：`usage()`（对方刚自己敲了命令、参数敲错）和
`commandMenu()`（帮助卡里那块折叠的"也可以用命令"）。

这条规则第一次跑起来查出 **104 处**违规——包括整份交接包（读它的人**从没用过这个机器人**）
和 6 个 OAuth 失败页面。第二次扩到 `skills/` 又查出 11 处：真机上它还在说"发 `/groups`"，
因为那句话不在源码里，**在我自己写的 skill 手册里**。

### 2.7 取舍六：出声的门槛是"有事要你做"，不是"我干了活"

以前每晚发一张卡：「候选记忆已整理：合并 3 组、删除 2 条」。用户的评价是对的——
整理很合理，给用户看没必要。

现在夜间整理**一个字都不发**。两头都站得住：

- 合并重复、删掉没价值的候选**只动没确认过的条目**，谁也没损失什么，没什么可汇报；
- 真需要拍板的事，正确做法是**在学到它的那一刻、在对话里问**，
  而不是攒到半夜发张折叠卡片，让人第二天自己去点开。

推广成一条：**半夜的批量通知，无论写得多短，都是把我的内务变成你的待办。**

### 2.8 取舍七：宁可说做不到

一组写死在系统提示里的行为契约：

- 群里回复**以 @ 提问的那个人开头**；涉及别人要做的事就一并 @ 上，@ 之后直接说他要做什么。
- **做不到的事，明说做不到以及为什么**（环境、权限、工具边界），并给出这个边界内还能做的那一步。
- **不索取他已经拒绝或确实没留存的材料**；自己能查到的不让他贴；确实要他动手时，把**可以直接复制的那一段**给出来。
- **发现自己上一条说错了，具体地更正那一条**（错在哪、正确的是什么）。
- 建单要四件事一起说清楚：**Issue 链接、记了什么、指派给谁、还不确定什么**。
- **合入不等于发布**，"在我查过的版本里没找到"不能说成"尚未发布"。

### 2.9 取舍八：别人维护的表格是事实源，我跟着它变

成员对照表（GitHub 登录名 ↔ 姓名 ↔ open_id）以前是一份 TSV 种子，
**装好那天就开始过期**，于是群成员显示成 `用户(a1b2c3)`。

那张表天天有人改（新人入职、有人换账号），所以正确做法不是灌一次，而是**自己定时读**：
启动拉一次 · 定时跟 · **查不到人时再拉一次**（节流 1 分钟）。
最后那档是关键——新人刚填上 GitHub 账号，不该回一句"不知道这个人"。

推广成一条：**凡是事实源在别人手里的东西，都不要在自己这边存副本，要去读。**
只读。Friday 从不回写那张表——它不是我们的账本。

## 第三部分：架构

### 3.1 总览

```
  飞书
   │  消息 / 卡片点击 / 机器人菜单
   ▼
┌───────────────────────────────────────────────────────────────┐
│  网关（单进程 Node + SQLite）                                   │
│                                                                │
│  ┌──────────┐   ┌───────────┐   ┌──────────┐   ┌───────────┐ │
│  │ 入站路由  │──▶│ 空间注册表 │──▶│ 上下文装配│──▶│ 执行队列   │ │
│  │ 谁在哪说  │   │ 找到/建空间│   │ 拼这一轮  │   │ 一空间一列 │ │
│  └──────────┘   └───────────┘   └──────────┘   └─────┬─────┘ │
│                            签发 capability ◀───────────┘       │
│                                    ▼                           │
│                        ┌────────────────────┐                  │
│                        │ 模型执行者（ACP）   │                  │
│                        │  + 按需加载 skill   │                  │
│                        └─────────┬──────────┘                  │
│                                  │ 每次调工具都带 capability     │
│                                  ▼                             │
│  ┌──────────────────────────────────────────────────────────┐ │
│  │ 内部 API（唯一入口，工具都从这里过）                        │ │
│  │  飞书读写 · GitHub · 记忆 · 待办 · 职责 · 报障 · 抓网页    │ │
│  └───────────────────────┬──────────────────────────────────┘ │
│                          ▼                                     │
│  ┌──────────────────────────────────────────────────────────┐ │
│  │ 交付账本：受众在发起那一刻锁死，发出去的每一条都留痕        │ │
│  └──────────────────────────────────────────────────────────┘ │
│                                                                │
│  SQLite：空间 · 记忆 · 待办 · 职责 · 游标 · 报障 · 交付账本      │
└───────────────────────────────────────────────────────────────┘
```

飞书和 GitHub 原始凭据由网关保管，不进入模型提示或 MCP 参数；工具请求由内部 API 核验。
**这不等于操作系统隔离**：当前 workspace 执行器和网关同 UID，原生文件读取仍可能绕过业务工具边界。
对外开放完整代码执行前必须完成独立执行环境验收，见 实际隔离探测。
受管工具模式的工具限制与操作系统隔离也分别验收，不能把提示词或分目录存放当成隔离证明。

### 3.2 空间模型

```
   张三的私聊空间        A 群空间           B 群空间
   ┌────────────┐     ┌────────────┐    ┌────────────┐
   │ 配置        │     │ 配置        │    │ 配置        │
   │ 记忆        │     │ 记忆        │    │ 记忆        │
   │ 职责        │     │ 职责        │    │ 职责        │
   │ 待办        │     │ 待办        │    │ 待办        │
   │ 读取游标    │     │ 读取游标    │    │ 读取游标    │
   └────────────┘     └─────┬──────┘    └─────┬──────┘
        只有张三自己           └──── 联盟 ───────┘
        看得到              （结盟后才互相可读）
```

- 空间在**第一次有人 @ 它**时创建。第一条 @ 只用来建空间，不干活。
- 建空间那一刻，**群主和群管理员自动成为本空间负责人**（一次性，之后换管理员不自动同步）。
- 群空间的成员 = 在这个群里和它说过话的人。

### 3.3 三层身份，不能互相顶替

```
  ┌─────────────────────────────────────────────────────────┐
  │ ① 应用身份（机器人自己）                                  │
  │    在**它所在的群**里说话、读消息、建文档表格、调 GitHub    │
  │    —— 决定"它能说什么"                                    │
  ├─────────────────────────────────────────────────────────┤
  │ ② 个人连接（你点按钮授权的）                              │
  │    私聊里用**你的权限**读你能读的东西                       │
  │    —— 决定"它能看见什么"，**只放大眼睛，不放大嘴**          │
  ├─────────────────────────────────────────────────────────┤
  │ ③ 读取范围（你的排除清单）                                │
  │    你明确停读的会话。默认全开，停一个只停这一个             │
  │    —— 只做减法                                            │
  └─────────────────────────────────────────────────────────┘
```

**② 不会让它多说一句话，只让它多看见一些东西。** 这句话印在授权卡正面。

#### 个人授权是分层的

以前一把要 13 个 scope，其中盯群那项要后台审批，**没批则整个授权页 20027 报错**——
于是个人授权一次都没成功过，而跨群搜索、历史检索、我的一天全挂在它上面。

| 层 | 内容 | 解开什么 |
| --- | --- | --- |
| `core`（默认） | 12 项；包含文档创建/编辑，并非全部只读 | 消息搜索、单聊历史、附件和文档；资源范围仍以本人权限为限 |
| `watch` | `im:message.group_msg:get_as_user` | 替你盯"你在、我不在"的群 |
| `calendar` | `calendar:calendar:readonly` | 看你自己的日程 |

**不要 `im:message`**（以用户身份发消息）：从来没用过，也不该用。

分层带来的义务是**别骗人**：能力判断看**飞书实际返回的 scope**，不是我们请求了什么；
连上之后回执说清楚哪些能用、哪些还要等后台。

### 3.4 一条消息的生命周期

```
  1. 有人在群里 @Friday：「这个报错是已知问题吗」
  2. 入站路由：哪个群、谁说的、是不是 @ 了我、属于哪个话题
  3. 空间注册表：找到 A 群空间（没有就建，群主设为负责人）
  4. 上下文装配：本轮消息 + 本空间记忆 + 相关话题 + 已登记职责
        （只带这个空间的，别的空间一个字都不带）
  5. 签发 capability：群会话 → GROUP_SCOPES，绑定这一轮，会过期
  6. 模型开工：先看 skill 目录，按需加载 bug-triage
        → 查重、读代码、读文档
        → 每次工具调用都要出示 capability，每个 await 之后重新验
  7. 要建 Issue？任何群成员都可以触发
     要改代码提 PR？生成确认卡，@ 群负责人，他不点就不动
  8. 交付：受众在第 5 步就锁死了，回答只能回到 A 群
        引用了别处内容的，末尾附一行来源披露
  9. 轮末整理：只提炼长期知识 → 候选记忆（要带来源）
        · 自己踩的坑 → 自查笔记（不展示给用户）
     待办在第 6 步的对话执行中增删改，完成后才回执；
     后台整理不能在回执发出后静默改写待办。
```

### 3.4.1 私聊是一条连续对话（2026-09-29 起）

群里每个话题、每件事各开一条会话；**私聊不是**。一个人和 Friday 的私聊就是一条连续对话：

- 空闲时收到的每条消息都接着当前对话继续——新问题、追问、一句"去看吧"，都不再被问"这条说的是哪件事"。模型自己记着前面几轮，长了由它压缩。
- 只有 `/new` 才重开；有任务正在跑时，新请求排在它后面，在同一条对话里做，不再另开一条什么都不知道的会话。分类器只剩两件事：有任务在跑时判断这条是插话还是停止；识别「记住：…」这类记忆操作。
- 对话里读过的东西（你在的群、日历、能打开的文档、团队仓库）都留在这条对话的来源记录上。**你自己看得到的，可以写进你自己的待办、提醒、定时任务**——原来"读过别的群这一轮就不能记待办"的规则在连续对话里会把一整天都锁死，而它保护不了任何人。三条仍然拦着：借别人身份读到的、你不能读的群、会议纪要和投票（各有自己的确认流程）。学到的东西要进**记忆**仍须带来源：从别的群里学来的走个人记忆那条有来源的路，只跟你本人有关的直接记。
- 读到的资料要是根本不能发给你（来源核验不了、属于别的受众），这条对话就没法再回答任何话；这时 Friday 会像 `/new` 一样重开对话并告诉你一句，之前的内容不再带入。
- 你转发别的群的消息、话题过来时，Friday 默认先用你的身份把原话题和前后文读一遍再说话，不问"要我去读吗"。

### 3.5 记忆分层

```
        企业层（org）          ← 只收管理员逐个授权、且完全公开的空间  🔜
             ▲ 晋升要负责人点头
        联盟层（circle）       ← 同联盟的群共享
             ▲
        空间层（space）        ← 默认在这里；A 群的不会进 B 群
```

每条记忆带**来源**：哪个空间、哪条消息、什么时候读的、当时用谁的身份读的。
来源失效了（比如撤销个人授权），**由它派生的记忆正文一并停用**，只留不含正文的壳和状态。

给你看的六种：事实、决定、待办、人物画像、规则、教训。
**不展示**的两种：一次性问答、它自己的工具限制笔记——对你没有意义。

### 3.6 受众锁定与交付账本

最容易出事、因此做得最死的一层：

- **受众在发起那一刻锁死**。模型不能执行到一半改主意说"这条发到别的群去"。
- 每次发送进**交付账本**，记下发给谁、发没发成、结果是否已知。
- **结果未知时不自动重发**——宁可让人去核对，也不冒重复打扰的风险。
- 只针对一个人的提醒**先私聊本人，不去群里喊**。对方不在这个空间、私聊不可达，
  就明确记下拦截原因，而不是退而求其次跑到群里喊。

### 3.7 进度游标：缓存和进度是两件事

- `chat_coverage(chat_id, start, end)` 是**缓存覆盖图**——"哪些时间窗已经在本地库里了，别再打 API"。
  **共用它是对的**：学习那轮抓了 10:00–11:00，盯群那轮直接读缓存。
- 真正的进度游标是 `routines.message_cursor_sec`，**一人一份**（一个盯群 = 一条职责 = 一个 owner）。
  推进只在读覆盖全了才做，而且是 **CAS**（要求配置版本匹配且游标恰在原位），并发的旧窗口推不动。
  消息发出去了但提交游标崩了 → 游标保持不动 → **下一轮重读同一个窗口**。

所以偏向重读，不会"读过但没汇报"。

### 3.8 PMO：按列定权威 ⚠️ 候选已实现，待飞书验收

表格里的人工更新可能与 Friday 账本不同。建行后，Friday 每轮读取当前表格，按列处理：

| 列 | 权威 | Friday |
| --- | --- | --- |
| 事项 / 负责人 / 截止 / 状态 | 表格（人写的） | **只读** |
| 「Friday 观察」 | Friday | 单向写 |
| 「风险」 | Friday | 提出；人可以清掉 |
| 「关联」 | Friday | 单向写：待办出处链接、待办里 Issue / PR 链接的只读状态 |

例如表格已改为「已完成 / Bob」，本地账本还是「进行中 / Alice」，观察列只陈述这两份记录，按表格的完成状态清除逾期风险，不改任一侧人工字段。观察和风险的依据是表格状态、负责人、截止时间和本地账本差异，不会把普通「更新时间」当成状态变更历史。「关联」列不参与风险判断：出处和待办卡片同一套呈现；Issue / PR 状态每张看板每轮最多读 24 个链接、同时 6 个，只读 FRIDAY_GITHUB_REPOS 允许的仓库，读不到写“未读到”。群活动证据尚未接入。

人清掉风险后，事实不变就不重写；「关联」一格同理，链接状态变了才重写。创建和更新均先占位，写后回读核对，读不到或不一致会保留「待核验」，不自动重发未知写入；之后每一轮（定时和手动相同）都再读一次表核对，核对上的条数记 info 日志 `pmo readback confirmed`，仍待核验的条数和原因（读表失败带平台错误码和原文）记 warn 日志 `pmo readback pending`，手动同步的回复也写明原因。旧版本行首次只建立读取基线，保留已有人工清空；「关联」列上线后的首轮只补这一列。每轮同步前补齐 Friday 自有的三列（人维护的列不补）；补不上，或表里已有人建的非文本「关联」列，这一轮不写「关联」（补列失败记 warn 日志 `pmo own columns unavailable`，带错误码；手动同步的回复写明原因）。范围仍是已绑定的当前群，中心化看板另行规划。

### 3.9 中心化进度视图 🔜

组长要的不是某个群的看板，是**横跨所有群 + GitHub 的一个视图**。
它回答的还是那五个问题，只是范围是全组：
这件事真的在动吗 · 卡在谁那里 · 什么要黄了 · 谁该知道 · 表里写的和现实一致吗。

权限上这是最危险的一件事，三条铁规则：

1. 只收**组长有权看到**的空间，逐个授权；
2. **汇总层不下钻**——能看到"A 群 3 件逾期"，点不进去看 A 群原话，除非他本来就在 A 群；
3. **私聊空间永不进入任何汇总**。

## 第五部分：使用指南

### 5.1 快速上手

**在群里用**（谁来做：想让它在某个群干活的人，也就是这个群的负责人）

1. 群聊右上角「设置」→「群机器人」→「添加机器人」→ 搜索 Friday
2. 在群里发一条 `@Friday` —— 这第一条只用来**创建群空间**，它不会基于这条消息干活
3. 这一刻，**群主和群管理员自动成为本空间负责人**（一次性授权）

**和它私聊**（谁能做：组织里任何人）在飞书搜「Friday」直接私聊。
想让它替你读群（**它不在那个群也行**），跟它说一声，它会把授权卡发给你。

### 5.2 怎么跟它说话

**默认用人话。** 命令是给已经习惯的人留的快捷方式，不用记。

| 你想要的 | 直接说 |
| --- | --- |
| 看现在什么情况 | 「现在什么情况」 |
| 看它在替你盯什么 | 「你都在替我盯什么」 |
| 看它能看到哪些群 | 「你能看到哪些群」 |
| 停掉某个群不让它读 | 「别读 xx 群了」 |
| 知道它凭什么这么说 | 「你怎么知道的」 |
| 让它记住 / 忘掉一件事 | 「记住 xxx」「以后别再提 xxx」 |
| 换个话题重开 | 「重新开一个话题」 |
| 让它停下 | 「停」，或卡片上的停止按钮 |
| 出个周报 / 整理成一页 wiki | 「出个周报」「整理成一页 wiki」 |

改行为习惯也直接说：「这个群攒一批再处理」「回答尽量短」「只有讨论排期时找我」。
它会记成这个空间的**常驻偏好**，原样放进以后每一轮的上下文。

> **权限划分**：日常行为相关的调整，普通成员就能提；
> 涉及权限、密钥、空间结构的，只有**空间负责人**（私聊里是你本人）的指令才会被执行。

### 5.3 谁能让它做什么

边界划在**"记录一件事"和"改别人的东西"**之间：

| 动作 | 谁能触发 | 为什么 |
| --- | --- | --- |
| 建 Issue、评论 Issue | **任何群成员** | 这正是它的核心价值。要求每次找负责人批，等于把这个产品废掉 |
| 建 Issue、评论 Issue、**开 PR** | 任何群成员，开完 **@ 相应的模块负责人** | PR 是提议不是改动：draft、要 review 才能合、关掉就没了。拦一道只会让它停在发起人那儿，@ 对人才会让它往前走。负责人取自仓库的 CODEOWNERS |
| 记待办、记记忆 | 任何群成员 | 自动提取的待办直接进清单，不对的自己删 |
| 改空间配置、换绑、停用空间 | 只有负责人 | 空间结构 |
| 个人授权、停读某个群 | 只有本人 | 别人无权替你决定它能看什么 |

### 5.4 群里的用法

GitHub 写入还需要部署者显式配置 `FRIDAY_GITHUB_WRITE_REPOS`。未配置或留空时只能读，不能建 Issue、评论、准备修改分支或发布 PR；读名单 `FRIDAY_GITHUB_REPOS` 不授予写权限。写名单也不能扩大读取范围。允许触发某个动作和允许写某个仓库是两道独立检查。

**当技术客服**（用户反馈群）：把仓库和文档权限给它，说「群里的提问主动接——先查代码和文档，
判断是缺陷还是设计如此；是缺陷就自己写代码、提 PR」。建单时四件事一起说清楚。

**当项目经理**（项目群）：告诉它进度表在哪、谁负责什么，「主动跟进进度并同步到进度表，
每天定时提醒当日任务、总结进展和风险」。

**当团队助理**（任何群）：长讨论后 @ 它「总结一下结论和待办」；
或排定时任务「每天巡查这个群，把新结论整理进文档或表格」。

**当产品设计师**（产品群）：「把这几个方案做个对比分析」；要看实物就「按这个方案出个原型」——
它会产出**可点击的 HTML 原型**，并说清这是原型不是已实现的产品。

**给新人导览**：「给这位新同学讲讲这个群之前在讨论什么、有哪些核心资料」。

**先在小群调教好再上正式群**：拉一个只有你和它的群，把偏好、记忆、职责调好，再换绑到正式群。🔜

### 5.5 私聊里的用法

**当盯群秘书**：「帮我盯着 xx 群」，再补一句关注重点（「只报和上线相关的」）。
默认**没命中重点就不打扰你**，不会发"本次无更新"。
汇报方式两种都行：直接发私聊；或归档——要读的落飞书文档，要筛选排序的落多维表格。

**当待办助手**：把相关聊天转发给它，再说「需要我跟进的记下来，负责人和时间没确定就先空着」。
记录时区分别人明确派给你的、你自己承诺的，以及需要你确认的建议。
新待办保存原请求和关联材料的出处，卡片可展开查看；旧待办不会自动补造来源。当前附件以转发容器为出处，不能据此声称附件内容已完整读取。
持续盯群需要先约定群和关注范围，再按个人授权实际可读范围执行；不默认监控全部群。
到期提醒**先私聊你本人，不去群里喊**。
想临时记一笔：「帮我记个建议/问题，先别建 Issue」——落成一条待跟进事项，能查、能关、能提醒。

**当问答搭档**：直接说要什么。它能结合你授权的那些群的讨论回答，末尾告诉你引用了哪几个会话。

### 5.6 授权与停读

```
   「你能看到哪些群」
          ├── 还没授权 ──▶ 一张带「打开授权页面」按钮的卡，点一下走完
          └── 已授权 ────▶ 清单卡： 正在读（N）… [停读]
                                    已停读（M）… [恢复]
```

**停一个只停这一个** · **恢复从上次读到的位置接着读**（中间不补发）·
被停读的会话再被问到，它会**点名说是哪个会话被停了、怎么恢复**，而不是回一句"找不到"。
「整个断开」跟它说一声即可，**断开后停读记录仍然保留**。

### 5.7 排查问题

| 现象 | 先看哪里 |
| --- | --- |
| 它答得不对 | 问「你怎么知道的」——会说清这轮读了哪几层、引用了什么、**没取什么** |
| 它凭什么这么干 | 看「它知道的事」，多半学错了某条；直接跟它说让它改 |
| 叫它没反应 | 问「执行到哪了」；或看执行卡片 |
| 想打断 | 说「停」，或点卡片上的停止按钮 |
| 定时任务是不是停了 | 问「你都在替我盯什么」——会列出下次安排和暂停原因 |
| 它做不到某件事 | 它应该**直接说做不到以及为什么**。绕过去或含糊其辞是 bug，请报给我们 |

**三种"停"是三件不同的事**：停**这一次执行**（「停」）· 停**这件事的后续跟进**（「这件事不用再跟了」）·
停**整条常驻职责**（「这个群别跟了」——会告诉你哪些定时任务被移除、已归档的表格还在不在、现在还盯哪些）。

## 第六部分：边界与隐私

**它会把群里的聊天拿去学习吗？别人能看到吗？**
会在**所在空间内**整理成记忆，只用于给这个空间干活。A 群的不进 B 群，私聊只有你自己可见。
企业层只收管理员逐个授权、且完全公开的空间；**私密群和私聊的内容绝不进池**。

**它会不会在我没说话的时候乱发消息？**
只在自己所在的空间里说话。没人 @ 它时拿到的能力**严格少于**被 @ 时——不发私聊、不发文件、
不碰 GitHub 写侧、不建定时任务。群里的主动回复可以关掉或调低频率。
**夜间整理一个字都不发。**

**我授权它读我的群，它会跑去那些群发言吗？** 不会。**个人授权只放大眼睛，不放大嘴。**

**凭据会不会进到模型里？** 不会。token 全在网关手里，模型只能请求"做这件事"。

**一个 Friday 能进几个群？每个群里的它是同一个吗？**
不限群数。但每个群、每个私聊都是独立空间，配置、记忆、职责互不影响——
**所以每个群里的它可以调教成不同的样子。**

---

## 第八部分：Friday 不做的事

**它不是一个"什么都能干"的机器人。** 做不到的事会明说做不到以及为什么，并给出边界内还能做的那一步。

**它不替你做判断。** 要不要建 Issue、这个方案选哪个、这个人该不该负责——它给依据和推荐，拍板的是你。

**它不在你没授权的地方活动。** 你没让它看的群，它看不见；不是"它自觉不看"，
是**它那张 capability 里没有这一项**。

**它不假装。** 读取失败不会写成"这段时间没有事项"；合入不会说成已发布；
分页截断、话题没展开、附件解析不了，都会作为**覆盖缺口**写在回答里。

**它不拿内务打扰你。** 自己整理记忆、自己踩的坑、自己的工具限制，都不出现在你面前。

## 四条原则

1. **一个同事装得下的事，就不要拆成一堆 agent 互相传话。** 交接本身就是成本。
2. **能用能力边界切掉的，就不要写进提示词里让模型自觉。** 提示词会被长上下文冲掉，没有工具是绕不过去的。
3. **被挡住的时候，给入口或者直接问，不要把命令甩给用户。** 它该替你省事，不是给你出题。
4. **出声的门槛是"有事要你做"，不是"我干了活"。** 我的内务不该变成你的待办。
